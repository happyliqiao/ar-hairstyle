# 镜界 AR 试发型

理发店场景的微信小程序：用前置摄像头实时试戴发型与发色，并根据人脸自动匹配推荐。

核心不是「滤镜」，而是**实时几何贴合**：把发型按人脸框的位置、大小、倾斜角实时变换后画在脸上，
换款、调大小、换发色都是即时生效的，不经过云端、不上传人脸。

---

## 核心功能

### 1. 实时试戴

- 前置摄像头 + `VKSession` 人脸锚点，逐帧拿到人脸框，发型跟着头动。
- 10 款发型：寸头、短碎发、波波头、齐刘海短发、长直发、大波浪、背头、羊毛卷、高马尾、中分长发。
- 12 种发色：自然黑、深棕、栗棕、亚麻棕、蜂蜜金、玫瑰金、红棕、酒红、蓝黑、灰紫、银灰、樱花粉。
- 手动微调：大小 / 上下位置 / 旋转，参数可存。

### 2. AI 自动匹配（`utils/match.js`）

纯函数实现，不依赖 canvas 与 wx，Node 可直接单测。

**脸型**：只能用人脸框的宽高比推（`VKSession` 不提供关键点）。

| 宽高比 | 判定 |
| --- | --- |
| ≥ 0.84 | 圆脸 |
| 0.70 ~ 0.84 | 标准脸 |
| ≤ 0.70 | 长脸 |

边界留 ±0.015 死区，贴边界时报「接近标准」而不是硬给一个结论。
侧脸会压窄宽度、把所有人都判成长脸，所以必须 `yaw rel ≥ 0.94` 才收帧。

**肤色**：CIELAB → ITA°。ITA 依赖绝对亮度，曝光一动就翻档，
所以同时算一路增益无关的旁证（HSV 饱和度 `(max-min)/max`），两路一致才自动替换发色，
不一致时只展示建议、不替用户做决定。

**排序**：脸型给出同档前三名（不只有一个答案），发色按目标明度距离 + 日常接受度排序。

### 3. 取景引导

固定的瓜子形取景框（`utils/face-fit.js`），三态状态机：`aligning` → `locked`。
给出「靠近一点 / 往左一点 / 别偏头」这类最多两条提示，对齐后 3 秒淡出，不挡脸。

### 4. 一次快门的四个落点

试戴记录、相册、分享、收藏。

## 技术要点

### 渲染

`utils/hair-engine.js` 是纯几何计算，不依赖 canvas 与 wx，同时服务 Canvas 2D 和 SVG 两个后端。
每款发型按 seed RNG（mulberry32）生成发丝，6 段色阶（shadow / deep / base / mid / tip / sheen），
8 层绘制管线，`high / mid / low` 三档细节。

真实绘制路径：`drawHair` → 离屏烘焙（`BAKE_SCALE = 3.0`，LRU 2 份）→ `drawImage`。
逐帧只做一次位图变换，不重跑几何。

### 存储

微信 `saveFile` 只有 10MB 配额，所以试戴记录做预算管理（`utils/store.js`），
超出按时间淘汰，并且不碰其他小程序写在同一个 storage 里的 key。

### 隐私

- 人脸画面只在端上处理，不上传。
- 相册写入走隐私协议门（errno 112 兜底）。
- `app.json` 的 `requiredPrivateInfos` 保持为空，不申请非必要权限。

## 自测

不依赖微信开发者工具，Node 直接跑。

```bash
# 全量：53 套
node tests/all.js

# 单套
node tests/face-match.js        # 自动匹配
node tests/guide-frame.js       # 取景框与对齐
node tests/render-check.js      # 10 款发型几何 / 覆盖率
node tests/perf-budget.js       # 性能预算

# 渲染截图（所见即小程序所见）
node tests/canvas-shot.js 900 black bob
```

测试用的手法：

- `utils/` 下的核心模块都是纯函数，Node 里直接 import，不需要模拟 wx。
- 页面逻辑用 Proxy 模拟 `ctx`，配合可控时钟（覆写 `Date.now` + `fireTimers(ms)`）验证定时器时序。
- 布局用无头 Chrome 截图 + `--dump-dom` 量高度，不靠「看着差不多」。

审计记录在 `tests/user-audit-*.md`，按轮次记录每一轮发现了什么、改了什么、为什么这么改。

## 已知限制

- **脸型只能靠宽高比**：`VKSession` 不提供关键点，判不出方脸，也无法区分骨骼。所以卡片底部永远留一个「判得不准？圆 / 标准 / 长」的手动出口。
- **yaw 门控是相对的**：基准取历史最大宽高比，如果进页面时前几帧全是侧脸，基准本身就是侧脸，仍可能误判。没有绝对头姿可补，只能靠手动出口兜底。
- **肤色只判深浅、不判冷暖**：两路测量打架时只展示建议，不自动替换。
- **脸型阈值（0.84 / 0.70）需要真机回归校准**：目前是几何推算值，建议用 20 张真实人脸验证后再定稿。
- **多张脸入镜未处理**：取第一个 anchor。
