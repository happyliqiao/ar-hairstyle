## 0. 这轮为什么换维度

第 9 轮把「屏幕形态 / 生命周期 / 流程边界」扫完了。这一轮不再重复，盯的是
**用户按下快门之后那 1~3 秒**：合成、落盘、写相册同时在跑，而页面上的按钮
全都还能点。这是此前 9 轮从未覆盖的区域，也是最容易出「照片和预览不一样」
「拍完找不到照片」的地方。

六个维度：

| 组 | 维度 | 轮次 |
|---|---|---|
| G1 | 真实操作序列：拍照期间用户还会点/拖/换/退 | R01–R10 |
| G2 | 并发竞态：多个定时器与异步回调同时到达 | R11–R20 |
| G3 | 数据一致性：预览 / 照片 / 记录 / 相册四者是否同一套 | R21–R30 |
| G4 | 性能压测：连续操作下定时器 / 内存 / 帧率是否失控 | R31–R38 |
| G5 | 跨页面状态：进出记录页 / 设置页 / 分享卡片后的恢复 | R39–R45 |
| G6 | 异常恢复：拍照 / 合成 / 落盘 / 权限的失败路径 | R46–R50 |

| R05 | 拍照期间进微调 | 不进入，避免滑块改了画不动 | FAIL | `busyShoot()` 挡住 |
| R06 | 拍照期间拖大小滑块 | 内存值不被改写 | FAIL | 滑块回调加 shooting 守卫 |
| R07 | 拍照期间双击复位 | 不改变拖动偏移 | FAIL | `busyShoot()` 挡住 |
| R08 | 拍照期间点返回 | 不退出，照片不丢 | FAIL | `goBack` 加守卫 |
| R09 | 拍照期间去记录页 | 不跳转 | FAIL | `goHistory` 加守卫 |
| R10 | 拍照期间点「换一款」 | 不换款 | FAIL | `nextRecStyle` 加守卫 |

**根因**：快门按下后只冻结了 `frozenBox` 和 `_captureLook`，但页面入口一个都没锁。
造型类操作会让 `data.currentStyle/currentColor` 变、冻结框不变，拍完 `unfreeze`
的瞬间画面跳一下；导航类操作更严重，页面一销毁 `compose` 的 `_alive` 检查直接
`return`，照片永远不写记录。

**修复**：新增 `busyShoot()` 统一守卫，覆盖换款 / 换色 / 微调 / 滑块 / 复位 /
换一款 / 用推荐 / 指定脸型 / 拖画面 / 返回 / 去记录页 / 收藏。同时 `render()`
在冻结期间改读 `_captureLook`，保证「预览就是照片」。

## 3. 四次自我否定

1. **R01 假失败**：`shootingPage()` 没设 `cameraReady`，`capture()` 第一个守卫
   就 return，`takePhoto=0`。不是产品缺陷，是测试漏了前置状态。

2. **R23 / R34 假失败**：在 `withClock` 外调 `store.listRecords()`，读到的是外层
   `global.wx` 的 storage，`n=0`。测试写法错，不是淘汰逻辑错。

3. **`freshPage` 框架缺陷**：`p.onLoad()` 在 `global.wx` 恢复之后才执行，
   `lastPick / favorites / calibration` 全读不到本场景的 storage，测试之间互相污染。
   修成「onLoad 也在 `env.wx` 下跑」，并支持 `opts.storage` 预设。

4. **R16 假失败**：`return` 写在 `withClock` 的 `fn` 里，结果没被正确取回。
   改成外部变量收集。产品侧的「清旧定时器」逻辑本身是对的。

**没有为了让测试变绿而放宽断言。** 13 个失败里 9 个改了产品代码，4 个改了测试
自身的前置状态或框架，断言一条没松。

## 6. 遗留限制

- **分享不受 `busyShoot` 约束**：拍照期间仍可转发，链接带的是「此刻的款」，
  照片里是冻结款。极端情况下两者不同，但分享是链接不是照片，优先级低。
- **拍照期间 `onResize` 仍会重算画布**：合成已用冻结视口，不会错位；但预览在
  尺寸变化的瞬间可能闪一帧。
- **`_captureViewport` 不在失败路径清空**：靠下一次 `capture()` 覆盖。数值是
  纯几何，不会累积，但严格说属于「懒清理」。
- **后台完成拍照依赖系统不挂起 JS**：`onHide` 后 `compose` 的回调若被挂起，
  只能等 20 秒看门狗复位；真机极端场景仍需实测。
